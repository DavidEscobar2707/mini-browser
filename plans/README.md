Generated by the improve skill on 2026-09-22. Execute in the order below unless dependencies say otherwise. Each executor: read the plan fully before starting, honor its STOP conditions, and update your row when done.

Product intent these plans serve: a coding agent working on a local app keeps one Mini debug window open, and Jev (`api.typesafe.ai`, the same judge `mini --qa` already uses) chooses each control the agent wants exercised. The agent states a goal and supplies field values. It does not send a blind CDP click. `mini --qa` stays a one-shot, write-refusing, login-refusing pass. These plans do not weaken it.

## Dependency notes

- 002 requires 001 because it tombstones the `ready` / `pid` record 001 introduces. A status command written against today's file would report a dead session as healthy.
- 003 requires 001 because `mini --move` attaches to the debug port, and that port dies today when the launching command exits.
- 003 requires 002 because `--move` must refuse a stale `current.json` instead of connecting to a dead port or a recycled pid.

## Findings considered and rejected

- Tabs, bookmarks, extensions, downloads UI: rejected in `docs/SPEC.md` §1 ("v1 does not"). Not part of this work.
- A hand-rolled "click the submit that shares a form with these fields" helper, with no Jev call: rejected. The operator asked for Jev to choose the control. Plan 003 passes `form_id` into the Jev question so the judge can tell the search submit from the login submit. The coding agent does not click.
- Running `mini --qa` against the local login as the way agents move: rejected. `--qa` wipes `%LOCALAPPDATA%\Mini\QA\profile`, refuses login/checkout URLs, drops controls labeled "sign in" / "log in", and blocks non-GET requests. That is the QA safety contract. Plan 003 is a separate loopback command.
- Opening the remote-debugging port from `--qa` so an outside agent can click during a QA run: rejected. `src/debug.rs` and `src/main.rs` already forbid that port unless `--debug` was passed explicitly.
